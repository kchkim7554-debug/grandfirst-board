# 게시판 관리 시스템 — 풍경채 그랑퍼스트 1단지

경비원 8명이 같은 링크를 열어 **실시간으로 함께 쓰는 게시판 관리 앱**입니다.
Firebase Realtime Database(무료 Spark 요금제)에 저장되므로, 한 사람이 체크하면 다른 사람 화면에 즉시 반영됩니다.

- 서비스 주소: https://kchkim7554-debug.github.io/grandfirst-board/
- 저장소: https://github.com/kchkim7554-debug/grandfirst-board

2026-11-26 전면 개편(시안 A). 민트색 바탕(#e5f6f1) · 흰 카드 · 둥근 모서리 · 큰 버튼.

**상단 바(고정)** — 왼쪽 **로고 + `게시판 관리 / 풍경채 그랑퍼스트`**, 오른쪽 **`실시간` 연결 칩 · `Admin` 칩 · ⚙ 설정 · `가+` 글자 크기**.
- 2026-11-26 사용자 요청 "상단바 하단바 지금 크기의 반으로 줄이자" · "밑에랑 똑같이" — 상단바 바탕을 하단 탭바와 **같은 파랑(네이비 그라데이션)**으로 통일하고 두 바의 높이를 절반(상단 74px→**40px**, 하단 76px→**44px**)으로 줄였습니다. 제목은 흰색, 부제(`풍경채 그랑퍼스트`)는 연하늘(`#a6c9e9`), `실시간` 칩은 반투명 민트, `Admin` 칩은 반투명 호박색, ⚙·`가+` 버튼은 반투명 흰색 테두리로 어두운 파랑 위에서도 또렷하게 보이도록 했습니다.
- 관리자 칩은 개인 이름 대신 **`Admin`**으로 표시합니다(동료와 같이 쓰는 화면). 누르면 담당자(조·구역) 선택.
- **⚙ 설정** 을 누르면 `시스템 권한 관리` · `풍경채 그랑퍼스트 정보` 로 들어갑니다(홈 메뉴에서는 빠짐).

- 상단: `--sat:max(8px, calc(4px + env(safe-area-inset-top, 0px)))` — 브라우저 창에서는 8px, 홈 화면(전체화면)에서는 상태바 높이만큼만 띄웁니다. (2026-11-26 상단바 절반화로 예전 `max(30px, …)` 강제값을 없앴습니다.)
- 하단: `--sab:max(6px, env(safe-area-inset-bottom, 0px))` — 탭바 높이 `--tabh(38px) + --sab` · 아래 여백 `--sab`. 안전영역이 없는 크롬·모바일 브라우저에서는 6px 만 두고 탭바가 **화면 맨 아래에 밀착**합니다. 안전영역이 실제로 있는 기기에서는 그 값만큼만 띄웁니다. (2026-11-26 사용자 지적 "하단 메뉴 맨밑으로 내려줘" — 예전 `max(50px, …)` 강제값이 탭바 아래에 흰 여백을 만들었습니다.)
- 탭바 바탕은 **파랑 계열**(네이비 그라데이션 `#1c4a7c → #123a63 → #0d2e52`)이고, 상단바도 같은 그라데이션을 씁니다(2026-11-26 사용자 요청 "밑에랑 똑같이"). 선택한 탭은 흰 아이콘·글자 + 하늘색 표시선(`#7dc4ff`), 나머지 탭은 연하늘 글자(`#bcd3ea`)로 시인성을 확보했습니다. 위 경계는 `border-top:1.5px solid #7fb2e4` + 위로 퍼지는 음영으로 본문 카드와 뚜렷하게 구분합니다. 탭 아이콘 16px · 라벨 `.56rem` · 배지 13px 로 슬림하게 맞췄습니다. 산뜻한 연파랑(`#eaf2ff → #dbe7fb`) 대안 값은 `index.html` 주석에 적어 두었습니다.
- 첫 화면 세로 간격은 2026-11-26 사용자 요청("간격 좁혀 · 1/2")으로 절반: 본문 위 여백 13→**7px**, 오늘 요약 ↔ `지금 처리할 일` 18→**8px**, 처리할 일 카드 사이 9→**5px**, 카드 안쪽 여백 12→**9px**.

## 처리 흐름

1. **등록(관리자)** — `#/create` `[생성]` 탭에서 **사진(첫 page만)** · 제목 · **동**(전체/복수) · **라인**(전체/복수) ·
   **게시판**(전체/1층/지하1층/지하2층 + 번호 01~12) · **E/V**(전체/호기 + 번호 01~06) · **생성일자(자동)** · **게시 기한**(달력/기한 없음)을 고르고 저장합니다.
   등록 직후 상태는 `게시 대기`이며 **도면에는 아직 나타나지 않습니다.**
   순번은 **자동**입니다(아래 '겹침 순번 자동 밀림' 참고).
2. **게시** — 담당 경비원이 체크하면 그 구역 도면에 즉시 게시됩니다. 구역마다 따로 체크합니다(정문/후문A/후문B).
   모든 대상 구역이 체크되면 `게시 중`이 됩니다.
3. **제거** — 기한이 된 게시물은 제거 대상으로 올라옵니다. 구역별 제거 체크가 모두 끝나면 자동으로 **보관함**으로 이동합니다.
   경비원은 현장 사정에 따라 `기한 변경`(사유 기록)을 할 수 있습니다.
4. **보관함(관리자)** — 날짜·번호로 찾고, 수정·삭제·`신규 게시로 재등록`이 가능합니다.

## 역할

- **조회**: 링크만 있으면 누구나 (로그인 없음)
- **경비원 체크**: 조와 구역만 고르면 됨(이 기기에 기억됨)
  - A조: 정문 염일엽 / 후문A 성연무 / 후문B 윤주한
  - B조: 정문 황보선희 / 후문A 김기춘 / 후문B 조명수
- **관리자**: `Admin`, `관리사무소` — PIN 4자리 (**초기 PIN 7554**, 관리자 설정에서 변경)
  - PIN은 평문이 아니라 SHA-256 해시로 DB에 저장됩니다.

## 🧪 테스트용 카피본 (`sandbox/`)

원본은 그대로 두고, 사용자들이 아무거나 눌러 보는 **버림용 카피본**입니다.

- 주소: <https://kchkim7554-debug.github.io/grandfirst-board/sandbox/>
- 상단 **흰색 고정 헤더(게시판 관리 / 풍경채 그랑퍼스트) 바로 아래**에 **`🧪 테스트용 (카피본) — 마음껏 눌러보세요`** 배너가 있고(상태바와 겹치지 않음), 탭 제목도 `🧪 테스트용 (카피본)`으로 시작합니다.
- **DB 완전 분리**: 원본은 `/board`, 카피본은 `/board/sandbox` 만 읽고 씁니다. 원본 `/board` 데이터는 카피본에서 읽기만 합니다.
  (Firebase 보안규칙이 `/board` 아래만 열려 있어 카피본은 그 안의 별도 키를 씁니다. 원본 `notices`·`config`·`logs`·`daily_alerts` 와는 섞이지 않습니다.)
- **자동 Admin**: 접속하면 PIN 없이 처음부터 `Admin` 권한입니다(등록·배포·삭제·기한 변경·권한 관리·설정 전부).
- 화면 코드는 원본 `app.js`·`data.json`·`images/`·`templates/` 를 `<base href="../">` 로 그대로 공유하고,
  `sandbox/env.js` 가 `dbRoot: "board/sandbox"`·`sandbox: true`·`lsPrefix: "gf.sandbox."` 를 넘깁니다.
- **초기화**: 챗에서 **"카피본 초기화해"** 하면 `python3 scripts/reset_sandbox.py` 한 번으로
  ① `sandbox/index.html` 재생성 ② 원본 `/board` 데이터 → `/board/sandbox` 덮어쓰기 ③ 확인 출력까지 끝납니다.
  (`--dry-run` 으로 무엇을 덮어쓸지 먼저 볼 수 있습니다.)
- `sandbox/index.html` 은 손으로 고치지 말고 `python3 scripts/make_sandbox.py` 로 다시 만듭니다(테스트가 동기 여부를 검사합니다).

## 게시물 제거 대상 일일 알림 (`제거대상 일일 알림` 메뉴)

매일 **07:00** 예약 작업(`scheduled-actions/📋-게시판-07시-탈착-알림`)이 그날의 제거 대상을 정리해
`/board/daily_alerts/{YYYY-MM-DD}` 에 1건씩 남기고, 웹은 이 경로를 실시간으로 구독해 날짜별(최신순) 피드로 보여줍니다.

```jsonc
/board/daily_alerts/2026-11-20
{
  "date": "2026-11-20", "weekday": "금", "shift": "B조",
  "hasTargets": true,
  "summary": "오늘(11/20 금) B조 제거 대상 2건",
  "items": [
    { "id": "R01", "title": "승강기 정기 점검",
      "location": "전층(1층·지하1층·지하2층) 공동현관 03번 첫 번째",
      "message": "전층(1층·지하1층·지하2층) 공동현관 03번 첫 번째 게시물 [승강기 정기 점검] 오늘 제거 바랍니다.",
      "memo": "선택",
      "cardImage": "templates/cards/2026-11-20_R01.jpg" }
  ],
  "events": [
    { "title": "승강기 정기 점검", "time": "10:00~16:00",
      "detail": "동별 순차 점검(101~121동) — 점검 중 1대 운행", "noticeId": "R01" }
  ],
  "createdAt": "2026-11-20T07:00:00+09:00"
}
```

- **대상 없는 날**: `"hasTargets": false, "items": []`, `"summary": "오늘 제거 대상 게시물이 없습니다."` → 화면에는
  `2026-11-19 (목) · 오늘 제거 대상 게시물이 없습니다.` 한 줄 배지로 남습니다.
- **`[알림]` 탭**: `년월일 | 내용 | 제거건수 | 담당(A조/B조)` 표. `최신순 ⇄ 오래된순`(역순) 전환.
  내용은 그날 제거 대상 게시물 이름(2건까지 + `외 N건`), 대상이 없는 날은 기록 문구를 보여줍니다.
- **`[선택조회]` 탭**: `from 년월 ~ to 년월` + `담당(전체/A조/B조)` + `[조회]` → 같은 표.
- **행을 누르면** 목록을 가리고 그날 **상세 화면**(`#/alerts/YYYY-MM-DD`)으로 전환됩니다. 위쪽 `‹ 일일 알림 목록` 으로 돌아오고,
  브라우저·휴대폰 뒤로 가기도 같은 곳으로 옵니다. 상세는 ① **📅 오늘 일어날 일(게시물 주요 일정)** → ② **🗑️ 오늘 제거 대상** 순서입니다.
  · ①은 `events` 에서 읽습니다(배열·Firebase 객체·문자열 모두 지원, `time` 또는 `start`+`end`). `events` 가 없으면 `등록된 주요 일정 없음`.
  · ②는 카드 이미지 크게 보기·저장, 안내 문구 복사, 위치와 `[오늘 제거 목록 복사]`(그날 안내 문구 전체 + 바로가기 링크).
- **카드 이미지**: `templates/cards/YYYY-MM-DD_Rxx.jpg`(합성 공지 카드)를 누르면 크게 보기 + `이미지 저장`.
- 항목 필드 별칭 허용: `title|name`, `location|loc|place`, `message|desc|text`, `cardImage|image|img`, `shift`는 `B`도 `B조`로 표시.
- 수동 추가(예: 보정):
  `curl -X PUT -H 'Content-Type: application/json' --data @daily.json https://grandfirst-board-default-rtdb.asia-southeast1.firebasedatabase.app/board/daily_alerts/2026-11-20.json`

- Firebase 프로젝트: `grandfirst-board` (Spark 무료, 결제카드 없음)
- Database URL: `https://grandfirst-board-default-rtdb.asia-southeast1.firebasedatabase.app` (싱가포르)
- 보안 규칙: `/board` 경로만 읽기·쓰기 허용, 그 외 차단
- 사진은 올릴 때 브라우저에서 900px·JPEG로 줄여(≈60~120KB) DB에 함께 저장합니다.

## 게시물 생성 및 이동 (`#/create`)

- **`[생성]` 탭** — 사진은 **첫 page만** 압축 저장(900px JPEG). 사진을 올리면 **제목을 1차로 자동 추출(OCR)**해 제목칸에 채우고
  「맞으면 그대로 저장, 틀리면 고친 뒤 저장」 안내를 띄웁니다. 이미 제목을 적어 둔 경우에는 덮지 않고 「이 제목 넣기」 버튼만 둡니다.
  OCR은 무료 `Tesseract.js`(CDN, `kor`)를 사진을 올릴 때만 불러옵니다. 저장용 사진(900px)과 따로,
  **원본 사진의 상단 35%(머리글 + 「제 목 :」 영역)만 가로 1600~2200px로 잘라** 그레이스케일·대비 보정한 이미지를 OCR에 넣습니다
  (작은 제목 글씨가 뭉개지지 않고, 아래 표를 읽지 않아 빠릅니다). 크롭은 PSM 6(한 덩어리 글), 사진 전체는 PSM 3(자동 페이지)로 읽습니다.
  「제 목 :」 표기가 있으면 그 뒤를, 없으면 머리글 아래 제목 크기 줄을 1차 후보로 씁니다. 「제 목」이 「멕 께 목」처럼 흐려 읽혀도 라벨 조각은 떼어냅니다.
  표의 한 줄·날짜·결재란(담당/과장/소장)·머리글(「풍경채」·「안 내 문」·「공고문」)은 **무조건** 제목 후보에서 빼고, 오프라인·인식 실패에도 막지 않고 직접 입력·저장이 그대로 됩니다.
  OCR은 브라우저 안에서만 돌고 **사진을 외부 서버로 보내지 않습니다**(내려받는 것은 라이브러리·언어 데이터뿐, `kor` 약 1.1MB).
  문제가 있을 때를 위한 진단구: 브라우저 콘솔에서 `window.__ocrDbg`(마지막 OCR 원문·줄·크롭 여부)를 보고,
  `window.__ocrPsm` / `window.__ocrMode`(`gray`·`bw`·`plain`) / `window.__ocrMaxW` / `window.__ocrLang` 으로 그 자리에서 튜닝해 볼 수 있습니다.
  게시장소는 **동 · 라인 · 게시판 / E/V**로 고르고,
  게시판은 층(전체/1층/지하1층/지하2층)과 번호(01~12), E/V는 호기와 번호(01~06)를 지정합니다.
  라인은 `1·2라인`·`3·5라인`·`1·2·3라인` 중 고른 라인에만 게시됩니다(도면 표시도 그 라인만).
  저장하면 `게시 대기`로 등록되고 아래 **목록**(`선택 | 구분 | 게시물 | 생성일자 | 게시장소 | 게시 기한`)에 바로 나타납니다.
  `선택 삭제`는 고른 게시물을 한 번에 지우고, 비워진 자리의 순번을 1,2,3…으로 다시 이어 붙입니다.
- **`[이동]` 탭** — 왼쪽 **현재 위치**(동·라인·게시판/E-V·번호)에 걸린 게시물을 골라 오른쪽 **이동할 곳**으로 한 번에 옮깁니다.
  도착지 순번은 기존 게시물 뒤로 이어지고, 원래 자리는 1..n으로 압축됩니다.
  옮긴 기록은 `board/logs`(type=`move`)에 남아 `최근 이동 기록`(`이동대상 | 이동할 곳 | 이동일`)으로 보입니다.

## 게시물 배포 (`#/deploy`) — 외부업체 게시·제거

- 게시 카드에도, 제거 카드에도 `A조`·`B조` 줄 아래 **`외부업체`** 줄이 있습니다.
  1층 게시판 5·6번처럼 **외부 업체가 직접 거는/떼는 게시물**은 담당자를 고르지 않고 그 구역 칸을 눌러 기록합니다
  (`attach[구역]` = `{ by: "외부업체", team: "EXT" }`, 제거는 `detach[구역]`에 같은 형식).
- 외부업체 기록은 A조·B조 칸에 체크(☑)가 켜지지 않습니다. 그 칸은 흐린 점선 잠금(`–` + `외부업체`)으로만 남고, 주황색 체크는 `외부업체` 줄의 해당 구역 칸에만 표시됩니다.
  A조·B조 담당자가 체크한 구역은 기존처럼 그 조 칸에 초록 체크가 켜지고 `외부업체` 줄은 잠금으로 남습니다.
- 제거 카드의 외부업체 칸으로 모든 대상 구역을 체크하면 게시와 똑같이 **보관함으로 이동**합니다(순번 자동 정리 포함).
- 제거 카드에서 **게시도 외부업체였던 구역**은 외부업체 칸 테두리가 주황 점선(`.chk.posted-ext`)으로 남아, 게시 상태가 제거 카드에서도 보입니다.
- 이미 담당자가 처리한 구역은 외부업체로 덮지 않습니다. 외부업체 기록 해제는 관리자만 할 수 있습니다.

## 게시물 통계 집계 기준 (`#/history`)

2026-11-25 개편 — 관리자 지시 "게시물 1건을 3명이 배포한 것이지 게시물 3건이 아니다"에 따라 원천 수정했습니다.

- **게시물 1건 = 게시 1건 / 제거 1건.** 정문·후문A·후문B 세 구역에 각각 걸어도, 담당자가 여러 명이어도 1건으로 셉니다.
  (이전에는 구역별 체크 기록마다 이벤트를 만들어 28건이 84건으로 3배 집계됐습니다.)
- 게시판과 E/V에 **함께 거는 게시물만** 게시판 1 + E/V 1 = 2건으로 나눠 셉니다.
- 담당(조)은 건수를 나누지 않습니다. 날짜별 상세에 담당자 이름(`염일엽 외 2명`)만 참고로 표시합니다.
- 날짜: 게시는 게시일(`postedAt`) 우선, 없으면 가장 이른 게시 체크 시각. 제거는 가장 이른 제거 체크 시각, 없으면 보관일.
- 테스트 게시물(`isTest`)은 제외. 체크를 취소하면 기록이 지워지므로 현재 기록 기준으로 셉니다.

## 겹침 순번 자동 밀림

같은 자리(게시판 + 번호 + 겹치는 층·호기 + 겹치는 동)에 게시물이 겹칠 때 순서를 자동으로 관리합니다.
**`order` 1 = 맨 앞(가장 나중에 붙인 것)**, 숫자가 클수록 뒤로 밀린 것입니다.

- **신규 등록** — 새 게시물은 항상 `order: 1`로 들어가고, 같은 자리에 이미 있는 활성 게시물(`status !== 'archived'`)의 `order`가 한 칸씩(+1) 올라갑니다. (1번째 → 2번째 → 3번째)
  기존 게시물의 `order` 변경과 신규 게시물 저장은 **한 번의 `update()`**로 함께 저장되어 중간에 어긋나지 않습니다.
- **제거 완료·삭제** — 자리가 비면 남은 게시물의 `order`를 1, 2, 3… 으로 다시 이어 붙입니다.
- **화면 표시** — 도면 칸은 1번째 게시물을 맨 앞에 보여주고 겹친 수를 배지로 표시합니다. 번호를 누르면 나오는 목록·이 게시판의 게시물 목록에 `1번째 / 2번째 / 3번째`가 그대로 나옵니다.
- **수정** — 관리자가 순번을 직접 바꿀 수 있습니다(1번째가 맨 앞).
- 겹침 판정: 공동현관 홀은 층이 하나라도 겹칠 때, 엘리베이터는 같은 번호(호기 지정이 겹칠 때)에 밀립니다. 동이 하나도 겹치지 않으면 밀지 않습니다.

로직 검증: `python3 test/run_quickjs.py` (Node 없이 QuickJS로 실행, 실 DB에 쓰지 않음)

## 홈 화면 아이콘

단지 조감도 사진 위에 네이비/민트 오버레이를 얹고, **`풍경채`**(작은 민트) / **`게시판관리`**(큰 흰색) 두 줄 글씨를 새긴 전용 아이콘입니다.

- 배경 — `images/bg_complex_aerial.jpg`(단지 조감도)를 가운데 정사각으로 잘라 은은하게 깔고, 네이비 반투명 그라데이션(위 75% → 아래 90%) + 아래쪽 민트 워시로 글씨 대비를 올립니다. 같은 사진을 `icons/icon-bg.jpg`(768px)로도 저장해 `icon.svg`가 같이 씁니다.
- 글씨 — 위 `풍경채`는 작은 보조 타이틀(밝은 민트 `#7ef5c8→#34d69e`), 아래 `게시판관리`는 주인공 타이틀(흰색). 둘 다 나눔고딕 ExtraBold로 잉크 폭에 맞춰 크기를 자동 계산합니다. 위쪽에는 민트 체크 배지(게시·제거 체크)를 둡니다.
- 파일 — `icons/icon-192.png` · `icon-512.png`(안드로이드 홈 화면) · `icon-maskable-512.png`(적응형, 글씨·배지 75%로 안전영역 안) · `apple-touch-icon-180.png`(iOS, 투명도 없는 정사각) · `favicon-32/16.png`(32px 급은 글씨 없이 흰 카드 + 굵은 체크로 간판화) · `icon.svg`(탭 아이콘, 글씨는 폰트 의존 없이 path 윤곽선) · `icon-bg.jpg`(아이콘용 사진 크롭).
- 연결 — `index.html` 의 `<link rel="icon">`(svg·32·16) · `<link rel="apple-touch-icon">` · `<link rel="manifest" href="manifest.json">`. 아이콘이 바뀌면 각 주소 뒤 `?v=` 도 같이 올립니다(캐시 버스팅).
- 다시 만들기 — `python3 scripts/make_icons.py` (색·모양은 스크립트 위쪽 상수에서 바꿉니다).
- 이미 홈 화면에 있는 바로가기는 아이콘이 저절로 바뀌지 않습니다. 바로가기를 **삭제하고 다시 추가**하면 새 아이콘으로 잡힙니다.
