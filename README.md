# 💓💓게시판 관리💓💓 — 풍경채 그랑퍼스트 1단지

경비원 8명이 같은 링크를 열어 **실시간으로 함께 쓰는 게시판 관리 앱**입니다.
Firebase Realtime Database(무료 Spark 요금제)에 저장되므로, 한 사람이 체크하면 다른 사람 화면에 즉시 반영됩니다.

- 서비스 주소: https://kchkim7554-debug.github.io/grandfirst-board/
- 저장소: https://github.com/kchkim7554-debug/grandfirst-board

## 화면 4개

| 탭 | 내용 |
|---|---|
| 동별 현황 | 오늘 탈착 대상, 부착 대기, 동별 게시판 그림(101~124동 · 코어 · 층 · 엘리베이터) |
| 부착·탈착 | ② 부착 체크 / ③ 탈착 체크 — 조·구역별 체크표 |
| 등록·관리 | 관리자 PIN 인증 후 ① 게시물 등록·수정·삭제, 담당자 설정, 테스트 데이터 삭제 |
| 보관함 | ④ 탈착 완료 게시물 — 탈착 날짜별·게시 번호별 조회, 수정·삭제·재등록 |

## 처리 흐름

1. **등록(관리자)** — 사진·제목·대상(전체/구역/동)·게시판(공동현관 홀·엘리베이터)·번호(01~12 / 01~06)·순번·기한 입력.
   등록 직후 상태는 `부착 대기`이며 **도면에는 아직 나타나지 않습니다.**
2. **부착** — 담당 경비원이 체크하면 그 구역 도면에 즉시 게시됩니다. 구역마다 따로 체크합니다(정문/후문A/후문B).
   모든 대상 구역이 체크되면 `게시 중`이 됩니다.
3. **탈착** — 기한이 된 게시물은 탈착 대상으로 올라옵니다. 구역별 탈착 체크가 모두 끝나면 자동으로 **보관함**으로 이동합니다.
   경비원은 현장 사정에 따라 `기한 변경`(사유 기록)을 할 수 있습니다.
4. **보관함(관리자)** — 날짜·번호로 찾고, 수정·삭제·`신규 게시로 재등록`이 가능합니다.

## 역할

- **조회**: 링크만 있으면 누구나 (로그인 없음)
- **경비원 체크**: 조와 구역만 고르면 됨(이 기기에 기억됨)
  - A조: 정문 염일엽 / 후문A 성연무 / 후문B 윤주한
  - B조: 정문 황보선희 / 후문A 김기춘 / 후문B 조명수
- **관리자**: `카일`, `관리사무소` — PIN 4자리 (**초기 PIN 7554**, 관리자 설정에서 변경)
  - PIN은 평문이 아니라 SHA-256 해시로 DB에 저장됩니다.

## 데이터 구조

```
board/
  config/      관리자 이름, PIN 해시, 조·구역 담당자
  notices/{id} 제목·사진(압축 Base64 또는 이미지 경로)·대상·기한·status
               attach{구역:담당·시각} / detach{구역:담당·시각}
  logs/        누가·언제·무엇을 했는지 기록(추가 전용)
```

- Firebase 프로젝트: `grandfirst-board` (Spark 무료, 결제카드 없음)
- Database URL: `https://grandfirst-board-default-rtdb.asia-southeast1.firebasedatabase.app` (싱가포르)
- 보안 규칙: `/board` 경로만 읽기·쓰기 허용, 그 외 차단
- 사진은 올릴 때 브라우저에서 900px·JPEG로 줄여(≈60~120KB) DB에 함께 저장합니다.

## 파일

- `index.html` — 화면(스타일·탭·헤더)
- `app.js` — 앱 로직(실시간 동기화·체크·등록·보관함)
- `data.json` — 시설 정보(동·코어·층·게시판 번호). 게시물은 들어 있지 않습니다.
- `notices_real.json` — 2026-11-16~17 현장 촬영 사진 19장을 판독해 정리한 실제 게시물 데이터
- `seed_firebase.py` — `notices_real.json`을 Firebase `/board/notices.json`으로 PUT 하는 스크립트(설정 `config`는 보존)
- `robots.txt` — 검색엔진 수집 차단 (index.html에도 `noindex`)

## 테스트 데이터

2026-11-17에 테스트 게시물(N01~N06, A01~A02)은 모두 삭제하고 실제 게시물 19건으로 교체했습니다.
(관리자 인증 → **등록·관리** 탭 맨 아래 `테스트 데이터 일괄 삭제` 버튼은 `isTest: true`인 게시물만 지웁니다. 현재 0건이라 눌러도 아무것도 지워지지 않습니다.)
